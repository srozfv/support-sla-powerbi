# SLA первого ответа техподдержки

Портфолио · Power BI Desktop · синтетические данные

Отчёт помогает руководителю поддержки определить, где чаще нарушается срок первого ответа, и найти заявки для разбора. В реальных системах SLA первого ответа может учитывать рабочие часы и паузы. В этом проекте действует упрощённый календарь 24/7 по UTC. [Microsoft Learn — настройка SLA](https://learn.microsoft.com/en-us/dynamics365/customer-service/administer/define-service-level-agreements).

## Открыть отчёт

1. Распакуйте архив целиком и откройте `SupportSLA.pbip` в актуальном Power BI Desktop для Windows. При необходимости включите форматы PBIP и PBIR в параметрах предварительных возможностей и перезапустите приложение. [Документация формата отчёта PBIR](https://learn.microsoft.com/en-us/power-bi/developer/projects/projects-report).
2. При первом открытии нажмите «Обновить сейчас» в предупреждении или «Главная → Обновить». Источник встроен в Power Query, учётные данные и пути к локальным CSV не нужны.
3. На странице «SLA первого ответа» выберите очередь, месяц создания или приоритет. Графики показывают динамику SLA и число нарушений. На странице «Просрочено без ответа» доступен список ID заявок и их дедлайнов. У каждой страницы свои фильтры.

## Правила расчёта

- `Tickets` — одно обращение на строку. Срез включает заявки, созданные с июля по декабрь 2025 года. `Calendar`, `Queues` и `Priorities` связаны с фактами отношениями 1:* с направлением фильтра от справочников.
- `DeadlineAt` = создание + цель в минутах (P1 — 60, P2 — 240, P3 — 1 440). Ответ, отправленный ровно в дедлайн, считается своевременным. Ответы после момента среза не видны.
- В знаменатель SLA входят обращения, у которых дедлайн наступил к моменту среза. Даже ранний ответ по ещё не созревшей заявке начнёт учитываться только после дедлайна. В числителе — созревшие заявки с ответом в срок. Пустой знаменатель даёт `BLANK()`.
- Нарушения включают ответы после дедлайна и созревшие заявки без ответа. «Просрочено без ответа» — только вторая группа, это состояние первого ответа на момент среза.
- Медиана в минутах считается по созревшим обращениям с наблюдаемым ответом. Дата фильтрует по созданию заявки, поэтому детализация просрочки показывает просроченные среди выбранных когорт.

## Данные и исходники

`data/Tickets.csv` содержит ID, дату и время создания, ключи справочников, дедлайн, дату первого ответа, время ответа в минутах и три контрольных флага. Пустой ответ или длительность означает отсутствие наблюдаемого первого ответа. `data/Calendar.csv` содержит календарную дату и ключ месяца; `Queues.csv` — названия очередей; `Priorities.csv` — названия и цели SLA. Персональных и коммерческих данных нет.

Power Query распаковывает встроенный снимок и типизирует поля. Меры DAX находятся в `SupportSLA.SemanticModel/definition/tables/Tickets.tmdl`, параметры страниц и привязки визуалов — в `SupportSLA.Report/definition/`. `checks.dax` — запросы для сверки показателей в представлении запросов DAX. `checks-detail.dax` проверяет набор строк детализации. Справочник ожидаемых результатов `expected.json` использует порядок: заявки, знаменатель SLA, в срок, доля (0–1), нарушения, без ответа с просрочкой, медиана.

## Сборка и проверка

Нужен Python 3.10+, внешние библиотеки для этих команд не требуются.

~~~sh
python generate.py
python build_report.py
python verify.py
~~~

Тесты сверяют встроенные данные с CSV, проверяют ключи и сроки, пересчитывают метрики из отметок времени и проверяют привязку полей визуалов. Контрольные строки охватывают ответ ровно в срок, ответ позже срока или снимка, отсутствие ответа, ранний ответ до наступления срока и нулевую длительность. Дополнительно JSON отчёта проверен по схемам Microsoft. Модель открыта и обновлена в Power BI Desktop 2.155.756.0. Семь мер DAX совпали с независимым пересчётом на общем итоге и по всем 24 срезам «очередь × месяц». Запрос детализации вернул ровно 163 ожидаемых ID просроченных обращений. [Результат выполнения DAX](results/dax.csv).

Ручная сверка в Desktop: на первой странице в исходном состоянии должны отображаться 4 800, 78,5%, 1 027 и 163. В очереди «Сеть» и месяце «2025-11» ожидаются 202 заявки, 43,1% SLA, 115 нарушений и 9 просроченных без ответа. На второй странице у очереди «Рабочее место» без остальных фильтров ожидаются 59 просроченных без ответа.
